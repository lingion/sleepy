**情况 1：在文件管理器里点 .html 文件 → 选"打开方式"→ Sleepy**

这个路径目前确实进不来。App 只注册了 JSON 和纯文本文件的外部打开，没有注册 HTML 文件类型，所以文件管理器里选 Sleepy 后什么都不会发生。这是缺口，下一版补上。

**情况 2：在 App 内 导入课表 → 从文件导入 → 选 .html**

这个路径是支持的（识别 `<table>` 表格后逐行解析），但解析失败时老版本的错误提示可能没显示出来，看起来就像"没反应"。

麻烦帮我确认两点，以便定位到底是哪种：

1. 你是**在文件管理器里用"打开方式"发给 Sleepy**，还是**在 App 内部点的"从文件导入"**？
2. 方便的话把这个 HTML 文件发上来（或贴一段表格部分的源码）。教务系统导出的页面格式千差万别——如果这个页面里没有 `<table>` 标签（很多新教务是 div 布局），现在的解析器也处理不了，这属于需要适配的新格式。

[大二课表学期1.html](https://github.com/user-attachments/files/31634990/1.html)\n\n### lingion — 2026-08-31T11:26:16Z\n\n你好，收到文件了。我检查了你提供的 HTML。

这个文件是 Excel 15 导出的 Frameset 网页，顶层的 `1.html` 只有框架和引用，真正的课程表在附属文件 `大二课表学期1.files/sheet001.html` 里。App 内选择文件时，Android 只把你选中的这个顶层文件 URI 交给 Sleepy，Sleepy 读不到旁边的 `.files` 附属目录，所以解析不到课程。

这类文件的关键问题是 Excel 的多文件网页结构，普通 HTML 表格解析器拿不到实际课表。当前版本已经能识别这种情况，并给出明确提示。

现在请把原来的 XLS 文件另存为以下任一种再导入：

- CSV 文件；
- 普通单文件网页，里面直接包含课程表的 `<table>`；
- 不要选择 Excel 的“单个文件网页/网页-筛选”这类会生成 `.files` 附属目录的格式。

我会继续评估 Android 文件选择器是否允许 Sleepy 在取得授权后读取这类附属文件；在不同文件管理器上这个权限行为不一定一样，所以暂时不把自动读取写成已支持。
