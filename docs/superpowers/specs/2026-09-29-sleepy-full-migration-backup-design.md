# Sleepy 全量迁移备份设计

## 目标

在“通用设置”中提供 Sleepy 全量迁移配置的导出与导入，支持换机/重装恢复。Android 先实现，iOS 后续严格对齐同一数据模型与协议。

## 用户可见格式

- 现有 `.sleepy` 继续表示 sleepy-v1 单课表文件。
- 全量迁移使用单文件 `.sleepybackup`，示例：`Sleepy-全量迁移-2026-09-29.sleepybackup`。
- 用户只选择/保存一个文件；内部为 ZIP 容器，内部文件不是用户操作对象。

## 包内数据边界

迁移包采用结构化数据快照，而不是直接复制 Android/iOS 原始数据库文件。内部按模块拆分，数据结构与两端严格对应：

```text
manifest.json
database.json
preferences.json
widgets.json
persisted_state.json
credentials.json       # 仅用户主动选择时存在
```

迁移范围覆盖当前所有可持久化数据：

- Room 数据库全部表及关联关系
- SharedPreferences 全部键值
- 小组件配置与平台实例快照
- 导入草稿、解析诊断记录、撤销/编辑历史
- 未来新增的持久化数据

不新增跨平台 UUID，不做内容推断或额外 ID 映射；保留现有本地 ID 与关系。纯运行时内存状态不迁移。

凭据是可选项：完整迁移默认不包含，用户主动选择后才写入；允许无密码导出，但导出前必须明确提示文件包含敏感信息。当前不允许明文凭据以外的扩展设计，未来能力可放入 `extensions/`，不可阻塞普通迁移。

## 导出流程

提供两种模式：

1. **完整迁移**：默认包含全部可持久化模块，仅单独确认是否携带凭据。
2. **自定义导出**：用户选择模块；系统自动补齐必要依赖，并在生成前展示最终实际包含的模块。

两种模式最终都生成一个 `.sleepybackup` 文件。

## 导入流程

1. 用户选择 `.sleepybackup`。
2. 读取 manifest 并解析包内容。
3. 展示数据摘要与模块清单。
4. 用户选择要导入的模块。
5. 对选中模块选择“覆盖”或“合并”。
6. 执行导入并展示成功、忽略、跳过及失败项。

导入规则：

- **覆盖**：选中模块全量替换本机对应数据。
- **合并**：保留本机数据，追加迁移包数据。
- 包内未包含的模块不删除、不重置：目标设备已有数据继续保留，没有数据则继续使用应用默认值。
- 未知字段/模块忽略并记录提示，不阻断核心导入。
- 无法恢复的平台小组件实例或凭据跳过并列入未恢复项。

## 实现边界

建议按职责拆分：

- `MigrationPackageWriter`：收集模块、生成 ZIP、写出 `.sleepybackup`。
- `MigrationPackageReader`：读取 ZIP、解析 manifest、发现模块。
- `MigrationModuleCodec`：各模块序列化/反序列化。
- `MigrationImportPlanner`：根据模块选择与覆盖/合并生成计划。
- `MigrationExecutor`：按事务或可回滚批次写入本地存储。
- `MigrationReport`：统一记录成功、忽略、跳过和失败项。

导出时冻结一次数据快照。导入必须先完整解析，校验通过后才写入；覆盖模式失败时回滚，不能留下半迁移状态。小组件只恢复目标平台能理解的实例记录，其他平台记录保留在包内并报告未恢复。

## 验证标准

- 导出后只产生一个 `.sleepybackup` 文件。
- 同一数据导出→导入后，结构化数据和关系保持等价。
- 覆盖、合并、自定义模块及自动补依赖分别有测试。
- 包内缺失模块不会改变目标设备对应设置。
- 未知字段、未知模块、损坏/不完整 ZIP 不会修改本机数据。
- Android 与未来 iOS 使用同一协议 fixture 验证兼容性。
