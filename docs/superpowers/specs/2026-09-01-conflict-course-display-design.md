# 网格视图课程冲突显示 — 设计文档

日期: 2026-09-01 · 状态: 讨论收敛，待实现 · 来源: GitHub issue #10 + 三张手绘草图 + 多轮讨论

## 0. 目标与范围

网格视图（CardsGridView）中同一天时间冲突的课程目前互相完全遮挡（同坐标同宽度叠绘，后画者盖前者）。本设计让簇内每门课都有视觉存在和可达入口。

**范围内**：仅 app 内网格视图。**范围外**（明确排除）：周视图 FullWeekView（逐行列表无遮挡，不动）、桌面小组件（等主页重做后另批移植）、冲突面板（被交换交互替代，不做）。

## 1. 冲突簇与主课判定（纯 Kotlin 引擎）

- **聚簇**：同一天内节次区间 `[startNode, startNode+step-1]` 相交的课程归为一簇（传递闭包）。
- **分组**：簇内按「节点区间完全相同」分为同段组（same-range group）。
- **主课判定**：时长（step）长 > 起始节（startNode）早 > id 小。纯数据确定性排序。不含 level 字段（导入链路从不填充，无数据）、不含长按固定（v2）。
- 视图收到的课已经过 `normalizeNode(timeJson)`（ownTime 课已折算成等效节点），引擎只对输入节点区间负责，不重复归一化。

## 2. 渲染分层规则（统一一条规则）

**变体标记的本质 = 给零露出课程人工制造露出。**

1. 每门课都绘制完整矩形卡：原节点区间、原高度、原课色；z 序 = 主课置顶，其余按判定序压下。
2. 梯形等异起冲突（1-3 / 2-4 / 3-5）：被盖课在独占节次**自然露出真卡**，不画任何变体标记。点独占段 = 该课与顶层**交换置顶**。
3. 完全包含（如 1-5 内嵌 2-3）与同段冲突：被盖课**零露出** → 顶层课按 §3 设置画变体标记标出被盖课。
4. 零露出状态每次渲染从 z 序重算，不缓存。

## 3. 三种变体 + 选择逻辑

设置项 `conflict_style` ∈ `stack`(A) / `fold`(B) / `rail`(C)，三选一，放 GeneralSettingsScreen 课表显示区（grid_sub_info 旁）。**默认 C。**

| 变体 | 形态 | 适用 | N≥3 处理 |
|---|---|---|---|
| A stack 叠层偏移 | 主体右下错位 d=4dp，露出 L 形边（次课课色） | 同段冲突 | **合流到折角形态**（4dp 边承载不了三层语义） |
| B fold 折角揭示 | 右上切角+翻折 flap（次课课色），s=12dp | **仅同起冲突**（完全重叠或同起不同止） | 折角 + N 徽标（见下） |
| C rail 侧边竖轨 | 主体右侧竖轨（次课课色），N=2 时宽 6dp；**N≥3 轨纵切 N-1 段，每段=对应次课课色+竖排课名**（复用 WeekGrid 字符级竖排截断逻辑） | 同起冲突 | 分段轨直达 |

- **B 的范围限定**：同起不同止（如 1-4 与 1-3）其实存在自然露出（短课的长段），此时 B 不画折角、走 §2.2 真卡露出。折角只在**完全重叠**时画。即 B 折角 ≡ 完全重叠场景。
- **N 徽标**：仅 N≥3 出现，N=2 不显示。**点击徽标 → 弹出课名选择弹窗**（BottomSheet/Dialog 列出簇内全部课程课名），用户点选谁置顶。
- **N≥3 设置为 A 的合流**：A 在 N≥3 时直接渲染为 B 的折角+徽标形态（B 与 A 在 N≥3 合流，用户表述"目前就打算只保留折角形态"）。
- **RAIL 混合露出簇**：混合露出 N≥3 簇（部分课自然露出）hidden 课数 <2 时仍渲染 6dp 单轨。
- 点击空间：视觉条窄（6-14dp），命中区**由 hit-test 人为放宽**（轨视觉宽+向内延伸），不靠 slop 补偿。常量集中定义，真机多次微调。

## 4. 交换交互（替代冲突面板）

- **点主体** = 编辑最上层课程（走现有 CourseDetailSheet，行为同无冲突卡）。
- **点露出部分**（真卡独占段、变体标记轨/L边/折角、N≥3 徽标弹窗选择）= 对应课程**与顶层交换**：被点课程升为完整可编辑主卡，原顶层降为标记层。
- 交换状态：**内存级**（rememberSaveable，旋转/切页存活，进程死亡后 rememberSaveable 可恢复 override，id 仍有效）。不做持久化。
- z 序交换后每门课的露出/标记状态重算（§2.4）。

## 5. 状态模型

- 引擎输出：`ConflictLayout` = 每课的几何（x/w/y/h）+ z 序 + 零露出标记归属。
- 交换 z 序：`Map<groupId或簇键, course.id>`（rememberSaveable），缺省 = 主课判定序。
- 设置读取同现有 AppPrefs 模式（KEY_CONFLICT_STYLE 常量 + getter）。

## 6. 文件结构

- Create: `util/ConflictLayoutEngine.kt` — 纯函数：聚簇、分组、主课排序、露出/零露出计算、变体分配。零 Android/Compose 依赖，可纯 JVM 单测。
- Create: `ui/component/ConflictCard.kt` — 三个变体的渲染 + 交换点击 + 徽标弹窗（Compose 层）。
- Modify: `ui/component/CourseTableView.kt` — CardsGridView 课程循环改走 ConflictCard。
- Modify: `util/AppPrefs.kt` + `ui/screen/mine/GeneralSettingsScreen.kt` — conflict_style 设置。
- Test: `app/src/test/java/com/lingion/sleepy/util/ConflictLayoutEngineTest.kt`。

## 7. 测试策略

引擎层单测（JUnit，无 Robolectric 依赖）必覆盖：完全重叠、同起不同止、部分重叠 3-4 vs 4-5、梯形 1-3/2-4/3-5、完全包含、互不重叠（回归）、不同天不同簇、同簇多组混合、主课判定三优先级 tie-break、交换后重算。UI 层依赖真机调（命中区、竖排、徽标弹窗），静态检查+构建验证；运行时验证仅 build/单测/静态检查（项目规则：禁跑 dev server/emulator，需要时先问）。

## 8. 已否决的备选

- 整囊分栏（34dp 列宽下文字区 ~5-11dp 不可读；且用户已定分栏仅归周视图）。
- 冲突面板（交换交互已覆盖可达性，多一个入口两套状态）。
- 持久化交换状态（课表周周变，key 难定无长期价值）。
- +N 徽标直接轮换置顶（改为弹窗显式选择，用户明确）。
- P8 字面执行（部分重叠只画主课会让次课独占节次从网格消失）。

## 9. 验收标准

1. issue #10 场景（完全重叠两门课）：两门课都可触达、可编辑，无互相遮挡不可见。
2. 梯形 1-3/2-4/3-5：三门课的独占段均显示完整真卡可点击。
3. 完全包含场景：内嵌课有变体标记可交换置顶。
4. 三种 conflict_style 均可切换且 N=2/N≥3 行为符合 §3 表。
5. `./gradlew :app:testDebugUnitTest --tests "*ConflictLayoutEngine*"` 全绿；`./gradlew :app:assembleDebug` 构建通过。
6. 既有全量单测无回归（JwProtocolFixtureMatrixTest 允许失败除外）。
