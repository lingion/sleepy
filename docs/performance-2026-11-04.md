# 页面切换与启动性能检查

本文记录基于 `c9d17102` 的四组性能优化及其组合验证结果：作息缓存、页面投影、渲染循环和后台任务。各独立分支的验证以对应 PR 的 CI 结果为准。

## 优化范围

| 场景 | 实现行为与验证条件 |
| --- | --- |
| 今日页面和课表页面来回切换卡顿 | 由主界面的同一个 ViewModel 保存最近三周的课程投影及当天课程分栏。返回页面时复用结果。课程、课表、作息或调休变化后清空旧结果，日期变化重新计算当天内容。测试检查复用、失效、调休、固定日期课程及缓存容量。 |
| 页面其他可能出现卡顿的地方 | 网格和周视图复用课程分组及排序结果。时间槽、校验和显示格式使用有界缓存，移除高频时间格式化中的通用 Formatter。主导航只订阅课表身份，翻周和选课不再使根导航跟着重组。浮动底栏的底部留白改为直接计算，消除组合期间写回状态。 |
| 优化启动速度 | 安装包缓存清理及小组件周期任务注册移至后台。撤回深度仍在首次编辑前同步初始化，旧通知清理仍在前台提醒恢复前执行，避免异步清理误撤回刚恢复的提醒。更新检查仍在旧缓存清理完成后启动。 |
| 动画、导入和列表 | 液态底栏的物理循环仅在动画或拖拽期间请求帧，静止时等待状态变化。文件导入的读取和解析离开主线程，节假日灰显计算移到后台，全部课表列表使用稳定身份。 |

## 保持的行为

底栏项目顺序、页面布局、转场效果、课程顺序、冲突分栏、周次选择及编辑入口保持原有设计。缓存只保存显示结果，不写课程数据库。时间字符串仍输出两位小时和两位分钟，测试遍历一天全部 1440 个分钟值。全局作息缓存每类最多 16 项，超过 32768 字符的输入不常驻；返回的共享时间槽列表不可修改。

## 检查范围

检查了启动入口、主导航、今日和周课表、拖课使用的课程分组、全部课表列表、课程列表、外观页、小组件管理及图库、文件导入与导出。课程列表原本已有分组缓存，小组件管理原本已在后台集中读取课表名称，导出和迁移文件操作原本已使用后台线程，这些路径沿用现状。

## 验证记录

原实现的 `TimetableDisplayCacheTest` 四项测试中两项失败，证实重复生成时间槽以及返回列表可被修改；原实现的已有性能测试三项通过。

最终验证使用 Temurin 17 和本机 Android SDK，执行命令为：

```sh
./gradlew --offline :app:testDebugUnitTest :app:lintDebug --max-workers=2 --console=plain
```

全量测试共 3685 项，3683 项通过，2 项跳过，失败和错误均为零。跳过项为原有 `WakeUpLiveCrossVerifyTest` 的两个外部握手测试。今日页、课表网格、冲突卡片和学校列表的五项像素回归均通过；新增的显示缓存四项、页面投影缓存六项及空闲帧循环两项全部通过。修正过新增测试的 JSON 替换范围及已有性能测试的反射方法筛选，最终结果来自修正后的完整重跑。

完整命令最终以退出码 0 完成，Gradle 输出 `BUILD SUCCESSFUL in 23m 15s`。lint 为零错误、594 条警告；这不是零告警结果。本轮没有修改 lint 配置或新增检查豁免。HTML 和 SARIF 报告位于 `app/build/reports/lint-results-debug.html` 和 `app/build/reports/lint-results-debug.sarif`。

成对性能测试在同一 JVM 内交替执行七轮，输入为 140 门课程，每轮模拟 30 次今日和课表往返的数据处理。重新生成的中位耗时为 43.893695 毫秒，复用结果为 0.086042 毫秒。这里只测课程投影、归一化和分栏，不含 Compose 绘制及手机输入事件。其他进程同时占用本机资源，因此不把绝对耗时或比例当作产品性能承诺，也不用机器耗时阈值决定测试是否通过。原有节点和行解析缓存不是本轮新增，不把已有缓存的对照结果算作本轮收益。

单测原始结果位于 `app/build/test-results/testDebugUnitTest/`。`git diff --check` 通过。

尚未取得真实手机的切页帧时间、冷启动到首帧时间和长期功耗数据。纯函数基准不能等同于整页帧率或启动加速比例；本记录不声称所有机型、所有数据规模都已消除卡顿。
