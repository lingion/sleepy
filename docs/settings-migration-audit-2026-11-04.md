# Sleepy 设置迁移与排序名单

审查日期：2026 年 11 月 4 日。以下记录 Android 设置重组前的问题、90 项迁移目标及固定顺序。实施结果和验证边界见同目录 `settings-reorganization-delivery-2026-11-04.md`。

源码审查基线为 `c9d17102a66956533f9e9bafc11be7465f2b3731`。完成条件为设置入口及子页均有明确归属，每个调整项目有唯一目标位置，迁移后保留原有偏好、作用域和操作确认。

**主要结论**

1. 底栏形态和底栏主题应放在同一组。现在形态在通用，主题在外观。
2. 课表显示分散于通用、外观和通用实验室，应按共同设置、周视图、网格视图、节次表头、冲突课程集中组织。
3. 假期的视觉灰显与实际调课规则必须分开。前者属于外观，后者属于课表安排。
4. 提醒的通知权限、精确提醒和电池诊断不应藏在流体云专属选项内。
5. 实验性质应作为功能状态标记，不能让相关选项散落到一个无主题的大杂烩页面。迁移时保留实验标识、默认值和原有确认。
6. 不重复实施主线已有变更：小组件已独立，刷新按钮已归入小组件，App 统一课程底色已整合进课程配色，导出已从我的列表移至管理入口。

**迁移的技术边界与验证要求**

这次主要迁移设置入口和展示顺序，不需要因为“迁移”二字更换 SharedPreferences 键或重建数据库。具体实现时必须保留以下行为。

- Dock 仍由应用层的同一状态控制；迁至外观后要连同状态回调迁移，不能出现设置值已变但底栏未刷新。
- 不改变默认值、不清空旧配置、不合并 App 与小组件各自独立的值。共享偏好须继续共享，页面位置不能暗中改变作用域。
- `displayMode`、显示星期、表头日期、最近有课日以及部分网格参数有小组件消费者；课程卡片副信息实际在 App 网格/冲突卡中消费，不能仅凭 setter 后调用刷新就宣称所有组件都受影响。
- 节次表头是视觉格式；作息表是实际时间。调休映射是课表课程来源；灰显是视觉效果。两组概念不得混用。
- 所有实验选项保留实验状态和原值。迁移实验选项并不等于宣布稳定，也不取消原有确认。
- 返回导航必须回到实际来源；已有外观内联内容改为课表显示子页时，需增加真实路由，不能只改标题。当前 `ScheduleDisplayScreen` 的独立函数不能证明它已有可达的导航入口。
- 颜色预览与保存时机、滑杆进页基线刻度、调休局部课表选择、每组件独立配置都需要保持。
- 调整现有 `MineWidgetEntryContractTest` 中对“最近有课日必须出现在小组件页”的旧断言，以同一共享偏好及新入口覆盖替代；保留通用与小组件相邻的断言，不能直接删除整个契约测试。
- 实施前先为新目录与父子顺序添加会失败的契约测试，再迁移至通过。至少覆盖 Dock 两项相邻、通用小组件相邻、晚间时间紧跟开关、两栏模式紧跟开关、删除位于保存之后。
- 实施后检查路由、原设置值保留、条件显隐、App 与相关小组件刷新、提醒重新调度、多语言标题和返回行为。最终实施验证见交付记录。
