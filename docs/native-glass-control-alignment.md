# Android 玻璃控件与 iOS 原生对照

2026-11-11 在 iOS 26.5（23F77）模拟器上，以未修改动画的 SwiftUI Toggle、segmented Picker 和 UIKit UITabBar，执行 XCTest 点击、长按和双向拖动。录屏逐帧观察与原生 presentation layer 的测量相互核对。以下单位为 pt；Android 按 dp 使用同一逻辑尺寸，触摸目标继续保留至少 48dp。

| 控件 | 原生静止 | 原生长按 | Android 对齐方式 |
| --- | --- | --- | --- |
| Switch 轨道 | 63×28 | 轨道不变 | 保留轨道和 22dp 行程 |
| Switch 滑片 | 37×24 | 58×38⅓，升起短暂约 60×40 | 分离几何过冲与透明度；实心填充随升镜淡出，收镜恢复 |
| 分段选择片 | 约 108×28 | 132×44 | 在实测的槽宽、高上增加 24×16；保留本地轨道尺寸 |
| 分段文字 | 1× | 1×，边缘局部折射 | 移除整段 1.16× 放大，仅由镜片做局部折射 |
| 底部 Tab Bar | 底座 274×62，片 94×54 | 底座约 1.0516×，片局部 110×70 | 保留已有底座缩放及片增加 16×16 |
| 底部 Tab 文字 | 1× | 片内局部 1.16×，另随底座缩放 | 保留底栏已有文字放大；不与分段控件混用 |

Switch 长按的滑片宽度拟合为质量 1、刚度 841、阻尼比 0.56 的弹簧；拟合含约 15ms 的起步延迟。分段选择片则单调升起，拟合刚度 635、阻尼比 1，约 20ms 的起步延迟；底栏选择片的局部升起与现有刚度约 632、阻尼比 1 的曲线相符。起步延迟包含触摸派发与首帧，Android 使用帧时钟和连续速度弹簧，不另插入固定触摸等待。

Switch 短按在第一次升起峰值后收镜；已越过峰值再松手则直接开始收镜，不等待后续微小振荡。分段选择片短按未升到完整长按尺寸就开始收镜，因此在松手时保留速度并转向收镜，不等待满幅或移动到目标。两者均允许收镜与横移重叠；约 250ms 的可见收镜过程恢复填充。几何允许短暂过冲，不透明度始终限定在 0..1。速度形变幅度按开关和分段分别缩小，避免套用大底栏的幅度；滑条继续使用原有曲线。

原生首次底栏交互出现模拟器首帧停顿，因此未使用该次点击拟合速度；底栏尺寸采用随后稳定长按的测量。分段短按确认部分扩张和收镜与横移重叠，但派发与首帧停顿使精确松手延迟仍不确定，未将该次短按延迟拟合为 Android 参数。此处为观察后的 Android 近似实现，不表示获得 Apple 的内部动画实现或光学着色器。

Android 首帧前合并的分段点击保留一个部分升起的反馈，再收回，避免按下与松手抵消后完全没有镜片变化。这是输入兼容处理，其最小幅度不作为 iOS 原生实测结论。

选中背景、文字和徽标直接读取当前 Material 配色。分段与浮动底栏共用 secondaryContainer、onSecondaryContainer、onSurfaceVariant、primary；Switch 和 FilterChip 保留调用方传入的 Material 颜色，包括禁用状态。透明颜色仍会与玻璃下方内容合成。

验证包括实际控件的按下、中间帧、峰值、长按、松手移动与落定尺寸，以及五套主题的浅色和深色 Material/玻璃颜色对比。Android 图形验证使用 Robolectric native graphics；未完成 Android 真机 GPU 对照。
